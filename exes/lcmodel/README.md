# lcmodel

A Rust port of LCModel 6.3-1N (S.W. Provencher, *Magn Reson Med* 30:672-679, 1993),
translated subprogram by subprogram from the BSD-3-Clause Fortran released at
[schorschinho/LCModel](https://github.com/schorschinho/LCModel) (commit
`c9d95ff9`). It keeps LCModel's algorithm, single/double precision and order of
operations, so it writes the same numbers as the Fortran compiled with gfortran.
`apps/lcmodel` runs it in the browser through `packages/lcmodel`.

```bash
cd exes/lcmodel
cargo build --release
./target/release/lcmodel < control.file     # as the Fortran: control on stdin, files by name
cargo test --release                         # includes the parity test below
```

The interface is LCModel's own: a control file (NAMELIST `/LCMODL/`), a `.RAW`
spectrum, an optional `.H2O` water reference and a `.BASIS` file, producing the
`.TABLE`, `.COORD`, `.PRINT` and `.CSV` outputs. `lcmodel::run_lcmodel` takes and
returns these files as strings. The PostScript report is not ported: set
`lps=0` (the browser app plots the `.COORD` file).

## Validation

* **LCModel's test case** (`tests/data/test_lcm`, from `test_lcm/` upstream):
  `tests/native_parity.rs` runs the port and compares every number in `.TABLE`
  (124) and `.COORD` (2117) with the output of the Fortran built with gfortran
  (`-O2 -std=legacy -fno-f2c -fno-backslash -fall-intrinsics`). They are
  identical; the files differ only in the date line.
* **A basis with a different bandwidth and length** (the FID-A PRESS TE 30 ms
  library set, 8192 points at 6 kHz, fitting the 1024-point, 2 kHz test data):
  identical `.TABLE` and `.COORD` again, exercising LCModel's basis resampling.
* **WebAssembly** (`packages/lcmodel/test/lcmodel-wasm.test.js`): the same
  concentration table; the `.COORD` curves agree to 6e-4 relative because the
  browser build uses Rust's `libm` rather than glibc for `sin`/`exp`/`pow`.
* **Per-module gfortran drivers** (`tests/*_vs_gfortran.rs`,
  `tests/data/*_driver.f`): FFTPACK for 28 sizes, PNNLS, the incomplete beta
  function, eigenvalues, NEXTRE/INFLEC, the priors parser, GBACKG, PENLTY,
  GETPHA, AREAWA and the FORMAT interpreter match the Fortran bit for bit.

Native run time on the test case: 4.1 s (the Fortran: 2.6 s).

## Layout

`PORTING.md` is the maintainer contract: the Fortran-to-Rust conventions and
where each subprogram lives. `src/state.rs` (every COMMON variable with its
BLOCK DATA value) is generated by `tools/gen_state.py`; `src/fortran.rs`,
`src/format.rs` and `src/io.rs` give Fortran arrays, strings, COMPLEX
arithmetic, FORMAT editing (checked against gfortran) and in-memory I/O units.

Known deviations, all where the Fortran is undefined: blank COMMON storage
shared by MYBASI, SOLVE and FINOUT is kept per module (see the comment on the
CHLESS path in `solve.rs`); uninitialised locals start at zero; `ICYCLE`'s fatal
error with a negative index panics.

## Basis sets

`basis/` holds the library the app offers: `library.json` (sequence, field, TE,
sampling), `simulate_library.m` (FID-A ideal-pulse simulations in Octave;
`sim_slaser_ideal.m` adds semi-LASER) and `make_basis.py`, which writes `.BASIS`
files: FID-A's FID conjugated as `io_writelcm` does, transformed with LCModel's
forward FFT scaled by 1/sqrt(N). The files are published gzipped in the Hugging
Face dataset `neurodeskorg/webapps` under `lcmodel/basis/`, pinned in
`models/lcmodel.manifest.json`.
